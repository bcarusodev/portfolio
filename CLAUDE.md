## Commands

| Command                                   | Description                                              |
| ----------------------------------------- | -------------------------------------------------------- |
| `npm run dev`                             | Start dev server (runs Velite build first, then Next.js) |
| `npm run build`                           | Production build (Velite + Next.js)                      |
| `npm run start`                           | Start production server                                  |
| `npm run lint`                            | Run ESLint                                               |
| `npx prettier --write --ignore-unknown .` | Format all files with Prettier                           |
| `node scripts/generate-blurhashes.js`     | Regenerate blurhash values for all project thumbnails    |

**Note**: No test suite is configured. Do not add tests unless explicitly requested.

## Tech Stack

- **Framework**: Next.js 15 (Pages Router, not App Router)
- **Language**: TypeScript (`strict: false` in tsconfig)
- **Styling**: Tailwind CSS + shadcn/ui (New York style, Zinc base) + Radix UI primitives
- **Content**: [Velite](https://velite.js.org) (migrated from ContentLayer) — markdown-based content management
- **Animations**: Framer Motion + Motion library
- **Fonts**: Geist (Vercel) via `next/font`
- **Theme**: next-themes (dark/light/system)
- **Formatting**: Prettier via Husky + lint-staged pre-commit hook
- **Analytics**: `@next/third-parties` (Google Analytics) + `@vercel/speed-insights`
- **Icons**: lucide-react, react-icons

## Architecture

### Directory Structure

```
src/
├── components/
│   ├── Atoms/          # Smallest reusable components (Brand, Layout, Title, ServiceCard, etc.)
│   ├── Molecules/      # Composed from atoms (ProjectCard, ContactButtons, SocialIcons, etc.)
│   ├── Organisms/      # Complex UI sections (NavBar, Footer, Hero, Services, AboutMe, etc.)
│   └── ui/             # Reusable primitives (shadcn-style: button, badge, drawer, sonner, etc.)
├── lib/utils.ts        # cn() utility using clsx + tailwind-merge
├── pages/              # Next.js Pages Router pages
│   ├── index.tsx       # Home page (Hero, Services, AboutMe)
│   ├── about.tsx       # About page
│   ├── work.tsx        # Project listing page
│   └── work/[id].tsx   # Project detail page (dynamic route)
├── providers/          # React context providers (ThemeProvider)
├── styles/globals.css  # Global styles, Tailwind directives, CSS variables
└── types/              # TypeScript type definitions (NavItem, SkillItem, TimelineItem, etc.)

data/
├── work/*.md           # Project markdown files (frontmatter + content)
├── work/loader.ts      # Static paths/props helpers, stacks icon map, project schema types
├── work/types.ts       # ProjectStackProps type
├── Hero.ts             # Hero section data
├── NavItems.ts         # Navigation items
├── Skills.ts           # Skills data
├── Technologies.ts     # Technologies data
└── Experience.ts       # Work experience timeline data

.velite/                # Velite generated output (import via @velite path alias)
public/static/          # Velite asset output directory
scripts/
└── generate-blurhashes.js  # Script to generate blurhash values from project thumbnails
```

### Path Aliases (from tsconfig.json)

- `@/*` → `./src/*`
- `@data/*` → `./data/*`
- `@velite` → `./.velite/index`

### Content Management (Velite)

Velite replaces the previous ContentLayer setup. It reads markdown files from `data/work/*.md` with frontmatter schema defined in `velite.config.ts`. Each project has fields: `title`, `description`, `topic`, `client`, `thumbnail`, `blurhash`, `detailImage`, `role`, `stacks`, and optional `projectLink`. The `id` is derived from the filename.

**Import change**: use `import { projects } from "@velite"` instead of the old `import { allProjects } from "contentlayer/generated"`.

### Component Patterns

- Functional components with hooks
- `React.forwardRef` + `displayName` for UI primitives
- `cn()` from `@/lib/utils` for conditional Tailwind class merging
- `class-variance-authority` (cva) for component variants (see button.tsx)
- `BlurFade` wrapper component for scroll-triggered entrance animations
- `useRouter` for navigation, `Link` from `next/link` for client-side routing

### Data Flow

1. Velite processes `data/work/*.md` → generates `.velite/index` with typed `Project` objects
2. `data/work/loader.ts` exports `getStaticPaths` / `getStaticProps` used by the [id] dynamic route
3. `stacksMap` in loader.ts maps stack IDs (e.g. `"react"`, `"aws"`) to icon components + display names
4. Pages import data directly from `@velite` (work listing) or via getStaticProps (detail page)

### Images

- Thumbnails use `blurhash` for low-quality image placeholders (generated by `scripts/generate-blurhashes.js`)
- Images are stored in `public/assets/images/work/<project>/`
- Uses `next/image` for optimized image loading

### Pre-commit Hooks

Husky runs lint-staged, which runs Prettier on all staged files before commit.

## Important Notes

1. **Pages Router only** — do not use App Router patterns (layout.tsx, server components, etc.)
2. **No test suite** — do not add tests unless explicitly asked
3. **Strict mode off** — `strict: false` in tsconfig.json
4. **Node.js 18+** required
5. **Do not use git worktrees** — Velite's generated content and build caching can conflict with worktrees
